# 연구계획서 md → PDF 렌더링 파이프라인

멀티에이전트 시스템이 뱉은 `proposal.md` 한 개와 다이어그램 `figure1.png` 한 장을
입력으로 받아, 표지·목차·본문을 갖춘 PDF를 만든다.
**md 원문은 전혀 수정하지 않는다.** 구조 해석은 전부 렌더러 쪽에서 한다.

```
input/proposal.md ─┐
                   ├─→ build.py ─→ build/proposal.pdf
input/figure1.png ─┘        ↑
                     assets/style.css
```

## 실행

```bash
pip install markdown-it-py beautifulsoup4 playwright pypdf pdfplumber
playwright install chromium

python3 build.py --md input/proposal.md --out build/proposal.pdf
```

메타 정보(표지 항목, 키워드, 그림 경로)는 `build.py` 상단 `DEFAULT_META`에 있고,
`--meta meta.json`으로 덮어쓸 수 있다. 시스템에서 문서를 생성할 때 이 JSON만
같이 뱉게 하면 표지가 자동으로 채워진다.

## 파이프라인 4단계

| 단계 | 하는 일 |
|---|---|
| 1 | `markdown-it`(CommonMark)로 md → 평범한 HTML. 2칸 들여쓰기 중첩 목록이 정확히 해석된다 |
| 2 | BeautifulSoup으로 의미 구조 부여 (아래 참조) |
| 3 | 소절의 실제 높이를 재서 한 페이지에 들어가는 것만 '통째 유지'로 표시 |
| 4 | 표지 / 목차 / 본문을 **각각 별도 HTML**로 Chromium에 렌더 |
| 5 | 본문 PDF를 pdfplumber로 되읽어 제목별 실제 페이지를 찾고, 목차를 확정해 세 PDF를 병합 |

4단계를 나눈 이유는 페이지 번호 때문이다. Chromium의 `footerTemplate`은
자기 문서 기준으로만 번호를 매기므로, 본문을 독립 PDF로 뽑으면 오프셋 계산 없이
본문 1쪽부터 자연스럽게 번호가 붙고 표지·목차는 번호가 빠진다.

## 2단계에서 md에 적용되는 변환

원문에 마크업을 추가하지 않고, 이 문서가 이미 갖고 있는 규칙성만 이용한다.

- **`## N. 제목`의 번호를 떼고 자동 채번.** 섹션을 추가·삭제해도 번호가 안 어긋난다.
  `h3`는 `1.1`, `1.2` 형태로 부모 번호를 물려받는다.
- **`#### 모듈 N: ~` 블록을 카드로 감싼다.** 다음 `h4`/`h3`/`h2` 직전까지를
  `<section class="module">`로 이동시키고 `M1` 배지를 붙인다.
  카드에는 `break-inside: avoid`가 걸려 페이지 경계에서 잘리지 않는다.
- **"라벨 + 하위 불릿" 패턴 재구성.** 하위 목록을 가진 최상위 항목의 머리 텍스트를
  `<span class="lead">`로 분리한다. 30자 이하면 굵은 산세리프 라벨
  (`입력과 출력의 정의`, `채택 근거`), 그보다 길면 완결된 문장으로 판단해
  일반 본문처럼 렌더한다. 이 분기가 없으면 1.2절처럼 라벨 자리에 긴 문장이
  들어간 절이 전부 굵게 나와 지저분해진다.
- **`- [그림 n] 캡션` 불릿 → `<figure>`.** 목록에서 떼어내 목록 다음에
  이미지와 캡션을 넣는다. 이미지는 base64로 인라인 삽입하므로 PDF가 자기완결적이다.
- **`[Ge et al., 2018]` → 배지 + 참고문헌 앵커 링크.** 참고문헌 항목의
  제1저자 성 + 연도로 키를 만들어 자동 연결한다.
- **참고문헌에 `[1] [2]` 번호와 내어쓰기**, URL 자동 링크.
- **`h3` 블록을 `<section class="subsection">`으로 래핑.** 페이지 나눔 제어의 기본 단위가 된다.

## 페이지 나눔 전략

내용이 페이지 경계에서 어정쩡하게 잘리지 않도록 세 층으로 막는다.

1. **장(`h2`)은 항상 새 페이지에서 시작** — `.chapter { break-before: page }`
2. **소절(`h3`)은 한 페이지에 들어갈 때만 통째로 유지** — 여기가 핵심이다.
   CSS `break-inside: avoid`를 모든 소절에 걸면, 한 페이지를 넘는 소절이
   통째로 다음 장으로 밀려 앞 페이지에 큰 여백이 생긴다. 그래서 렌더 전에
   Playwright로 **각 소절의 실제 높이를 측정**하고, 본문 영역(255mm)의 95%
   이하인 것에만 `keep` 클래스를 붙인다. `mm`는 절대 단위라 화면에서 잰 높이가
   인쇄 높이와 그대로 일치한다.
3. **모듈 카드, 그림, "라벨 + 하위 불릿" 묶음은 무조건 통째로 유지**

`build.py` 실행 시 `소절 9개 중 8개를 한 페이지 안에 고정` 같은 로그가 이 결과다.
(고정되지 않은 하나는 모듈 카드 3개를 품은 3.2절로, 애초에 4페이지 분량이다.)

**밀도와의 맞바꿈이 있다.** 장마다 페이지를 새로 시작하면 본문 채움률이
평균 61% 정도가 된다. 페이지 수를 줄이고 싶으면 메타에서
`"chapter_page_break": false`로 끄면 된다 (채움률 67%, 본문 1쪽 감소).
대신 장 제목이 페이지 중간에서 시작한다.

## 목차 페이지 번호를 얻는 방법

목차 항목은 모든 재구성이 끝난 뒤 최종 DOM을 훑어 **문서 순서대로** 만든다.
(모듈 카드가 h3 블록 안으로 옮겨지므로, 변환 도중에 목차를 쌓으면 M1~M3가
3.3절 뒤로 밀려 페이지 번호가 어긋난다.)

그다음 본문 PDF를 `pdfplumber`로 페이지별 텍스트로 뽑고, 공백을 모두 제거한 뒤
제목 문자열을 **문서 순서대로 순차 탐색**한다. 순차 탐색이라 이전 페이지에서
같은 어구가 나와도 잘못 잡히지 않는다. (`연구 주제`가 본문의 `연구 주제로 설정함`과
겹치지만, 그 본문은 어차피 같은 페이지에 있어 결과가 같다.)

두 번 렌더할 필요가 없는 것도 목차를 별도 문서로 뽑기 때문이다.

## 디자인 규칙

한 가지 강조색(`--accent: #2b4257`, 딥 슬레이트)만 쓰고 나머지는 잉크·회색조다.
색으로 구분하지 않고 **서체·굵기·여백**으로 위계를 만든다.

- 본문 Noto Serif CJK KR 10.3pt / 행간 1.80, 제목류는 Noto Sans CJK KR
- 머리글 없음. 바닥글에 쪽번호만 (표지·목차는 번호 없음)
- `word-break: keep-all`로 어절 보존, 참고문헌만 `break-all`로 URL 분리 허용
- 불릿 1단계는 강조색 정사각 마커, 2단계는 왼쪽 얇은 괘선 + 짧은 대시
- h2는 크기를 키우기보다 아래 1.2pt 강조색 괘선과 넉넉한 위 여백으로 구분
- 표지 하단은 작성자·작성일만

색·서체·여백은 전부 `assets/style.css` 상단 `:root` 변수에서 조정한다.

## 알아둘 것

- **Chromium은 `footerTemplate`을 본문과 다른 배율로 렌더한다.**
  대략 0.6배로 보이므로 원하는 크기의 1.6배쯤으로 지정해야 한다.
  (`build.py`의 `FTR`이 13pt로 잡혀 있는 이유)
- **머리글을 안 쓸 때도 빈 템플릿을 넘겨야 한다.** `headerTemplate`을 비워두면
  Chromium이 기본 머리글(문서 제목·날짜·URL)을 찍는다.
- **`build.py`의 `MARGIN_TOP/BOT/SIDE`와 `style.css`의 `@page body-page` 여백은
  반드시 같아야 한다.** 높이 측정이 이 값을 기준으로 하기 때문이다.
- **그림이 페이지 하단에 안 들어가면 통째로 다음 장 맨 위로 넘어간다.**
  `figure`에 `display: table` + `figcaption { display: table-caption }`을 줘서
  이미지와 캡션이 갈라지지 않게 했다. LaTeX의 `[t]` float과 같은 동작이고,
  앞 페이지에 여백이 남는 것은 정상이다.
- **PNG 해상도는 실제 배치 폭의 2배 이상**을 권한다. 본문 폭이 166mm이므로
  최소 가로 2000px 정도. 다이어그램 생성 쪽에서 SVG도 뽑을 수 있으면
  `<img src="data:image/svg+xml;...">`로 바꾸는 편이 인쇄 품질이 확실히 낫다.
- `build/_body.html`, `build/_cover.pdf` 등은 디버깅용 중간 산출물이다.
  브라우저로 `_body.html`을 열면 CSS만 고치며 바로 확인할 수 있다.
- `make_placeholder_figure.py`는 이 저장소를 단독으로 돌려보기 위한
  **임시 다이어그램 생성기**다. 실제로는 기존 다이어그램 프로세스의 출력을
  `input/figure1.png`에 놓으면 된다.

## 섹션 구성이 바뀌면

`restructure()`가 의존하는 것은 네 가지뿐이다.

1. `## 연구 요약` (또는 `요약`/`초록`) — 표지로 이동
2. `## 참고문헌` (또는 `References`) — 번호·앵커 부여
3. `#### 모듈 N: ~` — 카드화
4. `- [그림 n] ~` — 그림 삽입

그 외 섹션은 이름과 개수에 관계없이 자동 채번되어 흘러간다.

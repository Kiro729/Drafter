# Reviewer A — 내용 심사 (근거 · 정합성 · 데이터 구체성 · 논거)

## 역할

계획서의 **내용**을 심사한다. 한국어로 쓴다. 다음은 심사하지 않는다.

- 형식·분량·종결어미·금지 표현·강조·인용 위치와 형식·인용 논문 실재 여부 → `code/write/lint.py` 가 Writer 단계에서 이미 검사·수정
- 이해 가능성·논리 흐름·중복·모듈 균질성·설득력·연구 요약·AI 티 나는 표현 → Reviewer B

## 심사 기준 (PROMPT_REVIEWER_A)

| # | 기준 | REVISE 조건 |
|---|---|---|
| 1 | 근거 — 검색 결과로 확인되지 않는 사실·수치·기관명·연도, 추정치 표시 없는 규모 단정, 인용 논문과 주장의 부합 | 하나라도 있으면 |
| 2 | 섹션 간 정합성 9항목 — 세부 목표↔모듈, 학술적 기여↔세부 목표, 채택 근거↔미해결 지점, 지표 용어, 태스크와 데이터, 범위 밖 효과, 요약·연구명의 신정보, 연구 주제에 해결 방법 없음, 실험 및 평가에 목표 수치 없음 | 둘 이상 어긋나면 |
| 3 | 데이터 구체성 — 데이터셋 이름 / 제공 주체 / 형태와 항목 / 규모, 공개·직접 수집 구분 | 뭉뚱그린 표현이면 |
| 4 | 논거 — 미해결 이유가 구조적인가 | "연구되지 않았다" 로 갈음하면 |

## 검증 검색

- `PROMPT_EXTRACT_CLAIMS` 로 계획서에서 확인이 필요한 주장 3개를 쿼리로 뽑는다.
- 쿼리마다 Tavily 1회, arXiv 1회 (arXiv 는 `search.arxiv_call` 관문: 4초 간격, 429 시 5분 대기 1회 재시도).
- 결과가 프롬프트 끝에 `[Tavily 웹검색 결과]`, `[arXiv 학술 검색 결과]` 로 붙는다. 검색 실패는 "검색 실패" 블록으로 남기고 계속한다.

## 출력

```
VERDICT: PASS 또는 REVISE
FEEDBACK:
(기준별 번호. 각 지적은 "위치(섹션 > 항목) / 인용 불릿 / 문제")
```

코드가 `VERDICT:` 줄을 파싱해 `review_a_passed` 에 저장한다. Editor 의 통과 판정은 이 값과 `review_b_passed` 로 결정된다.

## 특이사항

- `increment_round=True` — 이 노드가 `review_round` 를 +1 한다.
- 이전 라운드 피드백이 `prev_feedback_section` 으로 들어가므로 반영 여부를 확인한다.

## 프롬프트 참조

`prompts/` → `PROMPT_REVIEWER_A`, `PROMPT_EXTRACT_CLAIMS` / 구현 `code/review/nodes.py`
